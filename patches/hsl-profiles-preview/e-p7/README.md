## 行为与边界

- 挂钩仍取代共同选择器调用 `0x603b14f3`，返回 `0x603b14f8`；原厂选择器先执行。请求必须为默认 COLOR、无自带表、不为 `0xf00d`，且有原厂请求回调、嵌入关系与 16 个合法操作记录之一。
- 图像所有者回调 `0x603e7b83` / `0x603e9631`：和 v2 相同，从所有者的快照读取模式和配置，不访问当前设置。无效快照保持原厂，不退回全局。
- 紧凑头回调 `0x60306ad5` / `0x6031b4de`，或回调与 owner 同时为零：只读一次叶 908 的单字节 `0x6250f836`，接受 1…4。其他头保持原厂。这些是原生构造身份；没有把回调名字当成完整工作流证明。
- 常量编码改为“先清除全部 24 个 H/L 半字，再应用每档两条偏移/值记录”，展开后与 v2 的 4 × 24 个值完全相同。原厂 S、其他控制字段和 LUT 不变。代码与表共 344 字节，位于已重验的段内范围，前后余量 64 / 184 字节。
- 同 S 切换不增加 dirty 标志：已提交默认请求会无条件重建 COLOR；原厂打包器每次设置系数写入位，两个 ISP 窗口都重新接收系数。完整菜单/帧调度、物理缓存一致性和实际画面仍由 B3 验证。

## 私有复验与确定性构建

Linux / WSL、Python 3.12；沿用未修改的 `tools/setup_t20_environment.sh`。固定上游及 GNU 源码校验要求不变。机主在本地取得原厂 1.1：111017984 字节，SHA-256 `9d1610124ad98f6edae4540182205f06c9c703d9033ef0c4f19847193f95eaeb`。

```sh
python3 tools/ep7_t24_1_probe.py \
  --upstream work/upstream/oly_fw_analysis \
  --stock /tmp/private/stock.BIN --out /tmp/private/v3-checks
python3 patches/hsl-profiles-preview/e-p7/build.py \
  --upstream work/upstream/oly_fw_analysis \
  --stock /tmp/private/stock.BIN --verify-only
```

`--verify-only` 校验组装、修改范围、完整解码主组件、编码往返及预期整包哈希；不生成更新文件。正常构建将最后一项换成仓库外、尚不存在的 `--out /tmp/private/v3-build`，由机主在审查后决定执行；输出仍禁止上传 GitHub。

## B3 · 仅供机主选择执行

1. 审查通过后在本地构建，核对 v3 / stock 的完整哈希、大小和 E-P7 1.1；供电、电池与备份沿 #49 已验证条件，SD 卡上同时只放选定的一个 `DCOLYMP/E1429999.BIN`。内部版本仍是 1.1，不能靠版本显示辨认包。
2. 先留原厂基线，再按机主已验证的 SD 流程装 v3。固定曝光、WB、光线和机位，使 COLOR1 / COLOR2 的 12 个 S 全部相同，对准黄色和深蓝物体，往返切档并**观察取景器**；另核对 COLOR3 的红/绿、COLOR4 无残留和 Natural 基线。
3. 每档拍摄后立即**观察自动回看**，再看相册回放与导出的 JPEG。预期三处与各档常量一致；记录正常停稳切换以及拍后立即切档的区别，必要时记录未插卡回看。v3 的预览/回看结果尚未经实拍证明。
4. 若异常启动、错误、卡住、非目标模式变化、残留或三处不一致，停止扩大实验，保留私人记录，按机主已验证流程安排恢复精确 stock；更新中不切电。正常启动恢复经验不等于独立救砖保证。

切换碰到全局字节读取时可能选择旧档或新档；单次读取后固定使用一整行常量，补丁不写任何设置。回看若晚于机主再次切档，也可能采用新档；最终 JPEG 始终走原有图像快照。模拟未覆盖 RTOS 队列深度或跨核物理时序，不能保证切换瞬态在实机上严格只持续一帧。
