# T26 · 配方预览与拟合工具

现在可以在本地载入 E-P7 的 JPEG / ORF，拖动参数预览、保存完整配方，并从 LUT 或参考照片获得拟合起点。
这是一套可校准的电脑近似模型，不会连接相机，也不保证预览与机内 JPEG 一致。
不同场景参考只能粗略匹配颜色分布；光线、局部效果、颗粒等不能由这些参数完整表达。
目前没有机主提供的标定照片，附带模型仍明确标记为未校准。

**做了什么**

- 基于合并 PR #60 的 main `d27654f`，实现原创 [Recipe Studio](../tools/recipe_studio/README.md)，未改任何固件工具、补丁或哈希。
- 复用 NumPy / SciPy、scikit-image 的色彩与 CIEDE2000 实现、Pillow 的 ICC/方向处理、rawpy/LibRaw 和 Flask。
- 固定参考 [fishcu@539fcf1](https://github.com/fishcu/oly_fw_analysis/tree/539fcf1fa9eda5fdef8ede4deeab94a4691d94c3) 的轮盘、H/L 单位、暗角符号/几何思路；没有复制上游代码、原厂表或曲线。
- 实现 40 个滑块、原图/效果分界、JSON 校验/导入/导出、三种拟合、保留像素与分色区误差，以及私人 RAW+JPEG 校准命令。
- 公开样片仅从 raw.pixls.us 的 E-P7 CC0 条目取用；真实输入、JPEG、截图与输出全部留在私有 `/tmp`，仓库只含源码和数字证据。

**结果**

| 验证 | 结果与边界 |
| --- | --- |
| 配方协议 | [版本 v1](../docs/recipe-format.md)：12 H/S/L、三段影调、暗角、名称说明、文字建议；严格拒绝缺失/重复/未知/越界字段。没有设备写入协议。 |
| 默认模型 | 编码 sRGB 的 HSV 调整：便于对已显影 JPEG 使用，不把相机内部色度空间冒充 RGB。环形余弦平方权重归一化，灰色降低 H/L 响应。 |
| H/S/L | H 初始斜率来自 T20 黄色观测；L 先按原生非线性单位转换，再用蓝色观测初始化全局强度；S 为指数增益。其他色区尚未实拍标定。 |
| 影调 / 暗角 | 三个平滑 Bernstein 亮度基函数；独立归一化双轴、径向平滑衰减、负混黑/正混白。曲线原创近似，不是原厂像素算法。 |
| 连续性 / 恒等 | 稠密色相环跨 0° 无断点；所有参数为 0 时数值严格保持输入；无色块硬切换。 |
| 已知参数回收 | 合成色图与真实样片像素上，模型生成的非零 H/S/L、影调、暗角目标均找回整数参数；未量化目标保留像素 ΔE00 为 0。只验证算法自洽。 |
| 8 位照片流程 | 模型目标保存 PNG 后重新载入，CLI 与浏览器拟合的平均 ΔE00 约 0.45、P95 约 0.95；不是独立相机精度验证。 |
| LUT | 原创标准 `.cube` / Hald 读入，三线性采样；恒等、轴顺序、DOMAIN、裁切及无效格式检查通过。Log/ACES/shaper 不支持。 |
| 参考图 | 按共同色区的 H 圆均值和 S/V 分位生成统计色块再拟合；最高评为“近似”，暗角不能辨识，保持初值。 |
| 校准 | 合成 RAW 显影数据可回收 RGB 增益/gamma 和已观测效果增益，验证保留场景误差；未观测效果不拟合，秩不足拒绝发布。真实实拍校准未完成。 |
| 浏览器 | Chromium 实际载入 ORF、调整、导出、拟合报告下载、配方重新导入通过；无脚本/控制台错误；390 像素窄屏无横向溢出。 |
| 测试 | 17 项工具测试；完整仓库 107 项中 102 项通过、5 项既有可选依赖跳过。新增 Python 3.12 专用合成 CI。 |

模型数值、范围和误差阈值集中在 [calibration.json](../tools/recipe_studio/calibration.json)。H/L −7…+7、S 默认 −5…+5，可配置为 ±7；影调 ±7、创意暗角 ±5。JSON 保存滑块步数，不保存角度、EV 或原生半字。全零表示对输入不改动，不代表四个工厂 COLOR 配方相同。

拟合用有界 SciPy 最小二乘优化 CIEDE2000（sRGB → CIELab D65），再整数化及有限坐标微调；质量取自整数结果的独立采样像素，报告每个色区的覆盖/误差、边界参数、未收敛和不可表达效果。像素留出仍来自同一场景，不是独立相机或跨场景验证；阈值只是可调的工作标准。

**风险与未知**

- 真实 ISP 色度空间、响应边界、S 增益、影调/暗角像素顺序尚未标定。JPEG 上调色属于二次处理；Natural、COLOR 默认、LibRaw 的基线不能混为一谈。
- ORF 用相机 WB、无自动提亮的 LibRaw sRGB 显影；嵌入 JPEG 的原始模式未知，仅用于解码流程测试。没有把它认定为 Natural/COLOR 标准答案。
- 成对照片必须手动确认对齐、曝光和 WB。RAW/JPEG 尺寸不同需显式裁切，不能靠自动缩放掩盖差异；校准至少需要中性训练对及独立验证场景。
- 校准目前只学习 RGB 增益/gamma 和已知配方的全局效果增益，不恢复色彩矩阵、色区形状或任意曲线；训练误差下降不等于真实匹配。
- 配方中 WB、偏移和 EV 只有文字建议；没有 Wi-Fi、固件、颗粒、设备操作或自动导入相机功能。未来 T25 必须另行核对能力和协议，不能直接发 JSON 到相机。
- 本地服务只监听 127.0.0.1；限制文件大小和预览尺寸，校验 Host/令牌/Origin，不缓存照片响应。输出拒绝仓库路径，不将照片/EXIF写入配方或报告。

**需要机主决定的事**

审查本 PR 后，可先在本机用已知 Natural/默认 COLOR JPEG 评价操作体验。若要提高机内预测可信度，再选择固定 WB/曝光的 RAW+JPEG、中性及已知非零配方、独立场景验证集，分别校准；无需色卡即可起步，但不能据此承诺色度精度。
本阶段已停止，不生成固件、不开启 T25 或其他阶段。复现与 Windows/macOS/Linux 安装见工具 README；许可、哈希和验证数字见[证据 JSON](t26-recipe-studio-evidence.json)。
