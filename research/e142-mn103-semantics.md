Actual run: three original fixtures each tested with all three GNU architecture selections. Normal/long-call fixtures exit0; a deliberately incorrect expected source-pointer result exits73. A separate **original synthetic cached-code control** exits9 under every selection, while the manual's cached initial immediate would remain7. GNU's pinned LNE implementation sets PC=LAR-4 and the tested engine refetches changed code; it is not a complete physical LIR model. The control modifies only its own temporary synthetic program, never OEM data. This negative result is preserved as a negative identity.

Manual p82's not-taken formula uses LAR+1 but also says execute following instructions; it conflicts with real fixture fallthrough when counter code extends beyond the cached4 bytes. Adopted sequential next-PC is supported by GNU implementation and original finite-loop tests; the contradiction is explicit. The same page's natural-language direction labels disagree with Boolean predicates. No attempt is made to hide these source limitations or emulate interrupts/cache coherence.

Only the existing26 windows are decoded; **GNU sim receives repository-owned synthetic ELF only**, never an OEM window, decoded image or reconstructed proprietary function.

- **Producer:** immediate counter at301d2b, SETLB301d2d, cached origin301d2e/LAR301d32, LNE301d33, exit301d34. Eight word reads/writes, matching A1/A0 increments and D1 counter. This is a copy, **not assumed zero filling**.

It assumes entry executes the shown setup, valid aligned nonvolatile buffers, no fault/interrupt changes and unchanged loop code. Nonoverlap is needed to claim original source-value preservation. Runtime addresses/data/cache behavior were not observed.
