# T25 · v4：H/L 存储、同步镜像与逐值 Wi-Fi

v4 已按机主修订实现逐值导入，不再要求相机一次原子写入整套配方。
H/L 写进原厂分部存储，并在原厂发布 COLOR 的 S 单元时更新镜像；成像函数不直接读 ACTIVE。
真实固件的离线分段执行已把标记请求连到设置写入、镜像、参数构造和两个 ISP 系数窗口。
这证明程序级数据流，不代表实机 Wi-Fi、冷启动持久性和 Myset 已验证；这些列入 B4。

**做了什么**

- 在 PR #67 分支合入最新 main `c805980`，复验固定上游 `539fcf1`、T20 setup 与原厂大小/SHA/容器；优先参考上游 Wi-Fi 设计，未复制其代码。
- 按 [#65 机主修订](https://github.com/ZakuZakuu/ep7-film-hack/issues/65#issuecomment-6423138124) 编写独立 v4、确定性受保护构建器、预期哈希和[正式协议](../docs/wifi-recipe-protocol.md)。旧版研究反证保留，不把放宽的验收要求冒充旧 blocker 已被实机消除。
- 复用严格 GNU 引擎、原厂注册表初始化/元数据注册、原有请求及 ISP 探针；新增有界原生端到端、格式拒绝、ABI、加载与引用分类实验。

**结果：修订后的离线验收通过；B4 未执行。**

**风险与未知**

- RTOS 串行投递/完成、HTTP 收发/分配、UI 一致性与非 HSL 消费者、后续应用通知队列为明确边界；真实注册转换、part 写入、COLOR 刷新、构造和寄存器上传执行原厂代码。不是整机系统或像素模拟。
- 只验证了声明的 CPU0/一致别名模型；没有证明物理跨核、缓存、DMA 或并发重载。引用分类也不能排除任意计算访问。
- 正常非易失保存、冷启动重载、Myset、单项/全重置和刷回原厂无害性按修订移入 B4。固件恢复不清空设置；早期 checksum/RAM bank 证据不冒充这些实测。
- 导入途中可能部分成功，处理中照片可使用新旧逐值结果；超时不代表取消，HTTP 200 不代表完整导入或持久化。客户端须备份、无自动重试、完整回读及不确定状态拦截。
