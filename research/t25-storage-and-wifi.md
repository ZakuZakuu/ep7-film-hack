# T25 · H/L 存储与 Wi-Fi 写入：未通过实现闸门

本轮验证了原厂分部 API 可以保存候选 H/L 单元，且 9 个内部 bank 在 RAM 中复制后可读回。
但 ACTIVE 会在召回提交前改变，当前配置和 inhibit 此时仍可能是旧状态，不能直接将它当作“当前已提交的配方”。
原厂单值 Wi-Fi 通道也没有提供已经验证的 40 值空闲事务与 payload 生命周期。
因此没有制作 v4，没有发布可用相机协议；依赖该协议的 T26b 不能按原要求继续实现，需先补齐这些连接。

**做了什么**

- 从 main `c805980` 开始，复验固定上游 `539fcf1`、T20 setup、真实 E-P7 1.1 大小/哈希/容器；没有操作相机。
- 先阅读上游存储/提交/传输研究，再复用严格 GNU 引擎和已有实验状态容器；新增的是有限原生存储探针，没有新建模拟器。
- 两条有界方法：直接通过原厂分部 API 读写/召回；再核对 inhibit / 应用编辑门禁能否补齐已提交与空闲条件。第二种不能单靠一个字节解决前一种的时序缺口。
- 原创候选单元编解码及测试、阻塞状态的协议文档；没有补丁源码、接收端、虚构预期哈希或安装文件。

**结果：部分原生机制通过；T25 整体验收失败，候选 A 仍有条件可用，不能发布 v4。**

| 项目 | 已执行事实 / 边界 |
| --- | --- |
| 格式 | 实验格式有版本/标记、H/L 有符号 4 位及互补字节；全部 225 个有效组合回收，未知/损坏/−8 中性回退。这不是已安装格式。 |
| 分部读写 | 432 次 CPU0 原厂 part 1 写入/读回通过，未改 part 0；没有用原始记录 setter 作为 H/L 写入口。目标为显式构造的 Mode RAM，不是相机存储实况。 |
| bank | 9 次原生 bank 保存、10 次读取，48 个候选单元保持；只证明两部分数组复制，不等于 9 个用户预设或完整 Myset 事务。 |
| 重置 | 48 个单项默认读取与 ACTIVE part 写入真实执行，候选解码中性；环境查询和已注册 current/staged setter 是明确模型，不能声称完整 UI 重置/保存已验证。 |
| 提交缺口 | 原生调用者的 bank-load 窗口已执行：ACTIVE 的 H/L 换成目标 bank，当前配置仍是旧值，inhibit 仍为 0；之后才有过滤、提交/通知等步骤。 |
| 门禁缺口 | 原生入口对测试字节 0/1/2/255 仅在 1 阻止编辑；未读拍摄/菜单状态，也没有取得 40 值事务。2/255 是反证输入，不是已命名的相机状态。 |
| 核心与运输 | CPU1 对当前 cached 指针进入原厂诊断边界，存储尚未改变；后续 RDI 重解析/跨核传递未重放。不能把 CPU0 实验当任意 HTTP worker 的执行保证。 |

| 兼容性 | 新扫描的 part API 直接候选主要为过滤、重置、调试及 raw 入口，未证明所有计算访问/刷回原厂后的解释；没有发现可据此直接宣称 A 已安全的证据。 |

**风险与未知**

- staging 窗口证明的是数据源与门禁不能直接等同，不是已经观察到实机混色；真实帧准入可能由更上层阻止，但本轮未证明。没有据此宣称候选 A 永久不可行。
- 旧 T24 已验证 checksum 覆盖候选字段，但本轮没有闭合正常非易失保存 → 冷启动重载、全重置、完整 Myset 召回与刷回原厂无害性。RAM bank 保存不能冒充这些验收项。
- S、影调和暗角仍须在原厂已注册设置路径中验证单位、范围及刷新。已定位的三段影调候选键与束内位置不直接冒充已验证的线上 setter 协议。
- 没有验证一次完整合法 40 值请求的 HTTP → 应用 → 刷新 → 保存 → 系数上传；非法输入整体无写入和超时所有权也未完成。不能用 HTTP 200、原始写入或自制 mock 填补。

替代路线评估：

- **A + 已提交发布边界，优先。** 在真正提交之后发布同一 bank 的 H/L，或证明读取期间原厂的静默条件；不必加每图像数值快照，但不能读到 ACTIVE 的中间态。
- **A 的 bank 读取变体，需后续验证。** 已有原厂 bank getter，可评估从已保存 bank 读取；必须先证明 bank 选择器与提交的关系，不能把 key 41 的中间值直接当已提交身份。
- **独立 SD 配方文件，暂不实施。** 避免 part 1 所有权问题，但仍需原生文件替换/重载、空闲导入与提交后发布；它不会自动解决本轮两个公共阻塞。
- **当前不写固件的电脑配方管理。** 现有 Recipe Studio 可继续离线编辑，不能把人工设置或纯模拟器称为自动 Wi-Fi 导入。

**需要机主决定的事**

建议下一次先做最小提交/准入实验：把目标 bank 的 part 1、当前 typed 配置、inhibit 与帧获得边界放进同一原生召回重放；再确定应用 worker 所在核心及一份请求从分配、投递、超时到确认/释放的所有权。通过后再编写 v4 接收端和冻结协议。
[协议文件](../docs/wifi-recipe-protocol.md)明确标为未发布，不提供可发送端点。T26b 依赖尚未满足，不能强行用猜测协议交付第二个功能 PR；若仅要离线客户端原型，应另行明确该缩小范围。
B4 当前不可执行：只有审查通过的 v4/协议存在后，才由机主选择“未写入中性 → 导入/回读/实拍 → 普通重启保持 → 重置中性 → 恢复原厂”的验证，本轮不执行。
