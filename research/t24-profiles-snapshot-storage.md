# T24 · COLOR1–4 的 H/L、图像快照与存储所有权

v2 能在已核对的图像所有者路径中，为 COLOR1–4 使用各自的 H/L 常量，不写入任何设置。相同饱和度往返切换时，这条路径会覆盖全部 24 个值并再次上传，COLOR4 会清除前一档的调整。另有紧凑请求路径尚未接通配置身份，v2 在该路径保持原厂效果，因此还不能承诺所有预览、连拍和 RAW 编辑都已覆盖。原厂重置会覆盖 part 1，备份与断电保护也未闭合，存储候选 A 只能判为有条件可用。

**做了什么**

- 基于 main `fba762f`，按最新版 AGENTS.md 和 Issue #58；复验 T20 setup，固定上游 `539fcf1`，只运行/参考其工具和方法。
- 阅读 [#49 机主实机结果](https://github.com/ZakuZakuu/ep7-film-hack/issues/49#issuecomment-6395587169)：T20 默认 COLOR 的取景预览、JPEG 与正常可启动状态下的原厂恢复已通过。这不替代 v2 的实拍。
- 原创独立 v2 补丁、确定性构建器与有限原厂函数探针；没有修改 T20 源码或哈希，没有写设置、连接相机或输出 v2 更新包。

**结果：已提交请求内的常量方案通过离线验证；原生切换全链路验收未通过，完整快照与持久存储仍有缺口。**

**存储所有权：只读分析**

- 候选 A **有条件可用**，并非空闲内存。复用 T22 已验证的 70 组 part 0 过滤及整档双 part 复制；新增原生逐键重置验证覆盖全部 48 个 COLOR 键，重置同时请求写入 part 0 / part 1 的原厂默认值。全重置还遍历所有键并保存全部内部 bank。
- Mode 后端会检测只发生在 part 1 的变化；原生校验和也覆盖这些单元。执行止于选槽之前，没有访问非易失写入后端。计数和校验存在，但 Mode 实际只配置一个非零后备地址；不能把通用双槽代码当作该设置区的冗余保证，更不能承诺断电原子性。
- Myset 复制可以携带 part 1，普通刷新不消费其 H/L 含义；调试/原始 API 能读取或请求改写指定 part。未穷尽所有计算指针消费者，E-P7 的命名备份导出/导入也未闭合。刷回原厂不等于清除这些值，原厂重置会以默认值覆盖它们；不能宣称刷回后的所有解释都已排除。
- 后续若使用 A，必须验证版本/范围并让未知数据中性回退，接受原厂重置清除配方，补上 bank 提交与备份契约后才写入。若这些条件无法满足，再评估 B：独立 SD 配方文件；其解析、掉电替换和快照仍未验证，本轮不实现。

**机主实拍方案 B2（仅文档，本轮不执行）**

1. PR 通过且机主另行授权构建后，核对 v2 与恢复原厂文件的完整哈希、型号和大小；机身 1.1、电池充满、照片已导出。安装沿 #49 已验证流程，卡上同时只放选定的一个升级文件。正常状态下的恢复测试不等于独立救砖保证。
2. 同一机位、光线、固定曝光和白平衡，先保留原厂每档基线；使 COLOR1 / COLOR2 的 12 色 S 完全一致。刷入 v2 后依次拍 COLOR1–4 和 Natural，并观察取景预览。
3. 预期：COLOR1 黄色关联区偏橙；COLOR2 深蓝关联区变暗；COLOR3 红色关联区色相改变、绿色关联区变亮；COLOR4 对应原厂 COLOR4，Natural 对应自身原厂基线。不同原厂档位的其他参数仍可能不同。
4. 按 COLOR1 → 2 → 3 → 4 → 1 和反向快速切换，停稳后拍摄；检查 COLOR4 没有上一档残留、各档预览与 JPEG 对应。未覆盖路径可能没有变化，需记录具体工作流，不能当作已实现全覆盖。
5. 异常启动、卡死、错误、非目标模式变化、上一档残留或预览/JPEG 不一致时停止扩大实验，记录现象，按机主已经验证的正常恢复流程安排刷回原厂；更新进行中不要断电。若不能进入该流程，不反复盲试。
6. 最后恢复精确原厂文件并复拍基线，确认补丁差异消失；内部版本号仍为 1.1，不能用版本显示辨别两个包。

**风险与未知**：v2 尚未实拍；紧凑路径、来源快照不可变性、缓存/DMA 并发及全部 RAW 路由未证明。设置模拟仅记录原生写入意图或操作自有 RAM，不代表相机持久化成功。同 S 的菜单提交 → 快照刷新 → 调度尚未闭合；若 B2 出现异 S 生效、同 S 不生效，应定位此上游链，不能靠未被调用的挂钩比较编号来补救。
