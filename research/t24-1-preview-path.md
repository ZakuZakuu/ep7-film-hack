# T24.1 · 取景预览与拍后回看

v3 已为核对过的紧凑请求补上按当前配置选 H/L 的路径；最终 JPEG 使用的图像快照路径保持 v2 行为。
四档常量没有改变，相同饱和度往返切换的离线请求会覆盖全部 H/L，再上传两个 ISP 窗口。
这些是原厂 CPU 参数和上传验证，不是预览、自动回看已在实机成功的结论。
v2 的原件与原哈希仍可复现；需要机主选择执行 B3，才能确认三处画面一致。

**做了什么**

- 从 main `f24340b` 开始，阅读 Issue #63、#58 的 B2 反馈及 T20–T24 结论；复验固定上游 `539fcf1` 和原厂大小/哈希/容器。
- 原创独立 v3 源码、清单和探针；复用已有受保护构建器、严格 GNU 模拟器、加载/上传验证，不复制上游代码，不改 v2 或 T20。
- 执行紧凑头生产/转换/复制、共同选择器路径、当前配置字节读取、相同 S 切换、强制切换时机、原路径回归及加载/初始化反证。
- 写明[构建说明与 B3](../patches/hsl-profiles-preview/e-p7/README.md)；具体地址、窗口哈希、对照与模型边界集中在[证据 JSON](t24-1-preview-path-evidence.json)。

**风险与未知**

- 已连通的是分段原生数据流与下游配置，不是整机 RTOS / 菜单提交 / 帧获得 / 显示的全程重放。两类回调身份来自真实生产者，不能仅凭位置给每个工作流命名；B3 仍须逐项核对取景和自动回看。
- 同 S 的已提交请求会重建并上传，但完整 UI 调度没有在模拟器中运行。T20 实拍取景有效提供正向旁证，不能替代 v3 同 S 切换实拍。
- 没有设置写入、可变配方、Wi-Fi、相机连接或其他效果。普通回放显示已有 JPEG，不是本补丁重新调色；未知请求头保持原厂，未承诺所有视频/RAW/连拍路径。
- 严格引擎会在未知访问停止；对象、栈、系数写窗口是显式模型，未模拟 ISP 像素或物理恢复。5 个代码区字面候选经成熟图像/压缩工具确认在编码数据中，仅用于放置核验。
- 本轮 Setup 遇到旧 GNU 缓存收据与新归档不一致，已保留旧缓存并从完整树重新验证构建，未改校验器、上游或源码身份规则。
