# T21 · COLOR 路径与安装退路（仅离线）

**做了什么**

- 基于已合并 PR #51 的 main `202d8c206470bf04a2d61f8490a3a020db258cc7`；按机主授权先完成 T21，再独立进行 T22。T20 补丁与预期哈希未变，没有生成新固件。
- 复用 T20 setup、GNU binutils 2.45 与 strict 模拟器；参考 [固定上游](https://github.com/fishcu/oly_fw_analysis/tree/539fcf1fa9eda5fdef8ede4deeab94a4691d94c3) 的 USB/恢复方法，不移用 PEN-F 地址或复制源码。
- 核对 COLOR 直接入口、参数分派与两条旁路，执行 4 个原厂选择器对照和 6 个 USB 门控对照；追踪 SD 任务与 USB 上传/校验/提交路径。

**结果**：完成有界调查，**仍不能保证拍照 JPEG、实时预览均经过 T20 挂钩，也未证明独立恢复**。所有地址均为 E-P7 1.1 CPU 静态地址；精确输入、窗口哈希、输入契约和复现办法见 [证据 E01–E09](t21-color-paths-evidence.json)。

| 问题 | 事实、反证与断点 |
| --- | --- |
| COLOR 所有入口 | 主组件逐字节相对转移/字面地址候选核对后，构造函数 `0x603b0068` 仅发现调用 `0x603b02d9`；选择器 `0x603b0252` 仅发现调用 `0x603b14f3`。其上为 `0x603aaced` 按请求类型/输入族选择 `0x603b17e6/0x603b1819`，另有明确关闭/替代系数路径。**这不是计算目标或动态回调的穷尽证明。** |
| 未覆盖分支 | 请求 +1524 非零且 dirty 位 `0x10000000` 置位时，调用 `0x603afb94` 从描述符 +16 的表复制系数；dirty 位清零时不更新输出。类型 `0xf00d` 时 `0x603b0247` 把输出 +976 清零。4 例均实际返回，后三例均不经过 T20 调用点。`0x603514d7` 是 `object+356+12` 的真实 `0xf00d` 写入者；尚未接通该对象到目标选择器。自带表的实际生产者仍未识别。 |
| 拍照、预览、连拍/低分辨率、RAW 显影、回放 | **五类均未闭合。** 断在原生用户工作流 → 对应请求所有者/字段生产者的关系；输入族 1/2、请求类型或函数相邻关系不足以给它们命名。默认条件满足时必经挂钩的模拟结论成立，但不能推成实拍覆盖。另一个原厂谓词 `0x603aade3` 在指定字段组合下直接选择关闭路径。 |
| SD 启动 | 任务 88 的描述符 `0x60039370` 绑定客户端 `0x60c95bab`；入口字面引用落在描述符，未发现直接调用。另查启动 API `0x60051a35` 的 309 个原始调用候选，前 16 字节未匹配 GNU 编码的直接常量 88；**仅是有限反证，不能排除计算分派。** 物理 OK/开机状态 → 激活任务 88 仍断开，不据此声称 SD 一定可用或不可用。 |
| USB 退路 | 原生注册代码绑定 `0x9119` 上传、`0x9125` 元数据、`0x9121` 校验、`0x9122` 状态、`0x9123` 提交。传输完成 `0x623380e4`、校验状态 `0x623380f8`、可提交 `0x623380e6` 为三个字段；原厂 readiness getter `0x60c49ac1` 仅在最后一个非零时返回 0。校验服务调用共享更新器 mode 2，提交服务为 mode 1。提交处理器发应用事件 `0x06000001`，但应用的异步回调/维护状态未完整接通。**有协议实现，不等于现成 USB 安装或救援方案**；本轮没有主机上传工具或会话操作。 |
| COLOR 崩溃循环 | 没有冷启动持久选择器重放，不能断言相机会记住 COLOR 并循环，也不能排除。SD 物理入口未接通，USB 依赖主应用与更新服务，均不能证明可在 COLOR 崩溃前到达。原厂 BIN 可再生成不等于有独立回滚执行层。 |

**风险与未知**：10 个新原厂对照均通过，模拟仅有声明的 ROM、对象和栈；USB 在服务调用前截停，未假造队列、硬件或写入成功。逐字节候选搜索有数据/错位风险，正向调用均再按 GNU 指令边界核对，负向结果保留范围限制。原厂数据、反汇编与执行轨迹只留私有 `/tmp`。**v2 仅设计**：若后续证明目标拍摄路径使用自带表，可考虑共同选择器返回点 `0x603b14f8`；必须先证明 COLOR 身份、原控制项启用、每图像快照来源和 dirty/upload 语义，覆盖默认/自带表/缓存复用/`0xf00d`/非 COLOR 及两个 ISP 窗口后才实施，不能直接全局改表或把关闭项重新开启。

**需要机主决定的事**：先审查上述覆盖与恢复断点；不要把 T20 当作已证明全拍摄覆盖或保证可恢复。A 阶段仍需机主独立核实 E-P7 操作依据并决定是否进行。本轮按授权继续 T22 的离线设计，两个 PR 独立等待审查，不启动 T23。
