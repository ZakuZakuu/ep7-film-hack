# 03｜技术研究路线与判定分叉

## A. 固件获得与最初分诊

1. 优先官方固件更新索引 / OM Workspace 的合法获取方式。**不推测官方下载 URL，也不在没拿到样本时宣称已解包。** 近期非官方直链不稳定，不能拿来当必然可用的基础。
2. 只读样本 inventory：型号、版本、来源 URL / 日期、字节数、SHA-256、已知头部字节、结构假设，放在私有研究区。
3. 先运行 `tools/inspect_blob.py`，再用 file、xxd、binwalk、7z、strings (ASCII/UTF-16)、标准解压算法分段探测。
4. 观察头部/尾部、高低熵区、压缩/加密迹象、分段对齐、校验或签名区域；保留原始证据和对应文件偏移。不盲猜加密算法。
5. 若有代码段，辨识架构（ARM 32/64, Thumb 等）、endianness、加载基址（待验证），再进入 Ghidra。**区分文件偏移、虚拟地址、运行时地址**。
6. 借助官方 GPL/OSS 软件通知和可能获取的源代码作交叉参考，但不假设它覆盖厂家专有 ISP 程序。

## B. 功能定位：从高置信低成本到高成本

1. 字符串 / 多语言资源：ART、Vintage、Cross Process、Instant Film、Profile、color 等（但资源文字不代表处理算法）。
2. 按菜单 ID、图标资源、滤镜变体表寻找引用（Xref），追踪数据来源和调用栈。
3. 检查配置结构、常量块、曲线、颜色矩阵、CLUT、ISP 命令参数。相似重复块、对齐和取值范围是线索而非结论。
4. 根据 jpeg/preview/RAW 开关的调用关系区分：实时取景、拍照输出、机内 RAW 处理是否共用路径。
5. 与其他 TruePic VIII 固件做符号/结构/常量层的相似性分析，**先求共性再讨论移植**。

## C. 关键决策树

### 分支 1：ART 样式主要来自静态表或 LUT

- 建立数据结构定义，输入空间/通道布局/插值方式/定点标度/校验验证。
- 先造合成资源与解析-序列化 roundtrip 测试，不修改设备。
- 输出最小、可追踪的离线补丁证明：变化范围仅在明确识别的表或对应配置。

### 分支 2：ART 由可参数化的固件软件算子构成

- 识别函数入口/调用者/关键参数及模式检查；研究可否组合不同处理算子。
- 不把“去掉互斥条件”当成必然安全：考虑缓存布局、处理顺序、帧耗时与预览/JPEG 差异。

### 分支 3：ART 主要固化在封闭 ISP/DSP 中

- 先探索可控的 ISP 配置表/命令接口，而不是“任意用户代码在硬件里运行”。
- 如果 ISP 不能自定义，评估存储后 JPEG 处理、RAW 开发路径或外部即时渲染；如产品体验不达标，要向用户明确报告。

### 分支 4：连官方固件都难以获得

- 不无限期猜包格式。转做可复现公开资料分析 / API 能力研究 / E-P7 RAW+JPEG 标准化样本 / PC 端电影风格模拟，保持与机内直出目标分离。

## D. Wi-Fi / USB 并行支线（从发现能力开始）

- 参考 `joergmlpts/olympus-wifi` 与 `dpolarov/olympus-view-and-delete`，先在不接真机情况下审阅 OPC 命令格式。
- 需要真机时，首轮只读：查询设备型号/版本/能力；记录只读响应，不扫描写入指令，不嗅探个人隐私内容。
- 列出配置相关潜在端点及**来源证据**。绝不可拿其他机型的命令直接盲写 E-P7。
- 若不存在写预设能力，不要把远程快门/传照片当成配方同步的证据。

## E. AI 与自动化使用原则

- AI 解读反编译结果只产生 *candidate interpretation*。对每一项解释必须有二进制偏移/函数地址/引用关系/差异实验支撑。
- 每个怀疑的 LUT 表都必须尝试反证：检查随机高熵数据、音频/字库、校验区域造成的假阳性。
- 非零进展的定义是：发现**新证据**而不是生成更多未经验证的推测文档。
