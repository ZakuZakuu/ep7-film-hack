# 05｜Cloud-first 执行计划与额度保护

## 工具分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| ChatGPT（本聊天） | 研究论证、产品取舍、阶段里程碑审查、关键证据反证 | 承诺远程持续后台执行 |
| Codex Cloud（主力） | GitHub repo、公开参考源码研究、只读工具、静态固件分析、自动化测试、报告 | 声称连接到家中 E-P7、未经批准执行刷机 |
| 本地 Codex / WSL / Windows | **必要时**只读 USB / Wi-Fi 探针、相机操作记录、合法个人固件样本保存；未来安全实机验证 | 默认替代云端一切开发 |
| Work（可选） | 对海量网页/资料做一次性整理 | 作为省 Codex 额度的保证（可能共享或受相近额度限制） |

云端无法直接访问本地 USB 相机；项目起步阶段不需要编译进机代码，云端生成的脚本、补丁/固件概念验证不能视为已可安全刷机。

## 任务拆分（一次只跑一项，限自动探索深度）

### T0：证据复核和仓库初始化

- 阅读本研究包。复核至少 4 条**关键事实**：E-P7 官方固件索引、软件声明 Linux、官方 ART 能力、GR IV README 明示范围。
- 创建目录、AGENTS.md、研究日志模板、可运行的只读工具测试；引用来源保留 URL 和核对日期。
- 验收：`evidence-ledger.md`，无虚构固件数据。发现来源失效即更新证据。
- 停止条件：不要开始模拟补丁或 UI。

### T1：官方固件可获取性

- 检查官方 OM Workspace 的合法获取流程。确认是否可能需要本地 E-P7 连接或许可授权。
- 有样本：本地私有环境保存样本，计算 SHA-256，不提交 Git；将**结构化、脱敏的**分析结果提交仓库。
- 无样本：形成 `firmware-acquisition-blocker.md`，停止猜测与搜索可疑固件镜像。
- 验收：固件证据链或明确阻塞。

### T2：容器/资源/ELF 静态分析

- 对合法样本执行只读 triage，生成 header map、entropy map、候选 segment table，记录每一步尝试。
- 对 Ghidra 反编译只对候选位置做定向分析；不要把全面手工分析固件视为默认任务。
- 验收：可验证文件偏移、结构、哈希或说明数据受保护/样本不足。

### T3：ART 过滤器线索

- 追踪资源中的 ART 名称、ID、变体、参数、可能的 CLUT 和处理路径；反证误识别。
- 若不具备 E-P7 固件样本，做单独的 public-source hypothesis report，不得出“已定位”结论。
- 验收：可信候选表 + 证据清单，或 go/no-go 评估。

### T4：**可选**只读真机调查

- 仅在用户准备好并单独授权后，把查询步骤写成 `READ_ONLY_DEVICE_PLAN.md`，由用户在本地执行。
- 不发送任何有副作用的 HTTP/USB 指令；捕获的 SSID、设备序列号、图片、个人目录不公开。
- 验收：E-P7 实际能力列表/响应的脱敏摘要。

### T5：离线颜色处理原型

- 对自己拥有版权的 ORF+JPEG 样本构建参考图像管线，展示胶片模拟 LUT + 曲线 + 颗粒如何组合。
- 这个模拟器**不是 E-P7 内置 LUT 的证据**，只验证视觉目标和色彩科学。
- 验收：至少 3 种不同光照的图像上展现视觉一致性，附曝光/白平衡限制。

## 额度保护（与具体订阅额度无关）

- 每轮一个可证伪问题 + 一个交付物，禁止“一口气实现所有功能”的长任务。
- 默认单 Agent，不以多 Agent 并行扫描未知镜像。
- 两次不同方法仍无新证据：停止本轮，提交失败记录和 next-best experiment。
- 安装 Ghidra、大型模型或环境之前，检查是否确有样本和具体任务；无样本先做资料审查。
- 对探索出的每个重要分支保存 5 行简报：目标/输入/证据/结论/下一步；后续从报告续做，不反复重复分析。
- 由用户界面实时额度决定任务规模，**不预估固定每周可做多少工作**。

## Git 策略

默认单私有 repo，`main` 保持可复现，研究通过单任务分支 + PR 进入；无无效自动 PR 风暴。产出包含源码/脚本/分析 Markdown/合成测试数据，不包含原厂固件和相机照片。
