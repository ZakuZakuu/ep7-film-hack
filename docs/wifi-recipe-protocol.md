# E-P7 Wi-Fi 配方协议 EP71 · v1

本协议对应 T25 v4、E-P7 / E142 1.1，按 [#65 机主修订](https://github.com/ZakuZakuu/ep7-film-hack/issues/65#issuecomment-6423138124) 采用**逐值**应用。正式命令契约如下；离线链路验证与完整预期固件哈希见 [v4 清单](../patches/hsl-recipes/e-p7/patch.json)及[证据](../research/t25-v4-evidence.json)。**尚未经 B4 实拍验证**，不表示真实断电持久性已经通过。

设计参考 [fishcu 固定提交的 WIFI.md](https://github.com/fishcu/oly_fw_analysis/blob/539fcf1fa9eda5fdef8ede4deeab94a4691d94c3/docs/protocols/pen-f/WIFI.md)。编码、代码和地址为 E-P7 独立实现，不兼容 PEN-F HSL1；禁止客户端回退到无标记的原始写入。

## 连接、身份和会话

- 机主通过相机原厂**私人 Wi-Fi**连接电脑；默认 HTTP 地址 `192.168.0.10:80`。工具只允许 RFC1918 私网 IP 或测试用回环 IP，不跟随重定向、不使用 HTTP 代理。
- `GET /get_caminfo.cgi`：原厂 XML 根 `caminfo` 的 `model` 必须精确为 `E-P7`。仅提取型号，不提取、记录或导出序列号、MAC 或整份响应。
- `GET /get_mcon.cgi?mode=FFFF`：v4 返回 `45503731`（ASCII `EP71`）；同版原厂的未知编号返回 `00000000`。其他值、HTTP 错误、格式错误均视为不兼容，**禁止任何写入，包括 S**。标识不是密码学认证，也不远程证明安装包哈希。
- `discover` 只做上述只读检查。明确执行写入时，完成身份检查后先请求原厂 `GET /switch_cammode.cgi?mode=rec`，再备份并写入；不启动取景流或拍照。沿用原厂应用状态准入，不绕过拒绝，也不发明一个“已验证空闲”字节。
- 目标是当前应用设置上下文的 COLOR1–4；不直接选择或覆盖 9 个内部 bank。请机主在 PASM 下执行 B4；Myset 保存/召回另测。`rec`、`play` 或 HTTP 200 均不是经过证明的保存命令。

## 读取和逐值写入

所有 `mode` / `value` 数字均为**十六进制**，无 `0x`、正负号或空白。标记写入的 `mode` 为 1–4 个十六进制字符（客户端固定发 4 个），`value` 恰为 8 个十六进制字符。大小写均可。

读取响应沿用真实原厂格式：HTTP 200，XML 根 `response`，恰有一个 `value` 子节点，其文字为 u32 十六进制，例如 `<response><value>FFFFFFFE</value></response>`；可有 XML 声明。将合法负值按二进制补码转为有符号 32 位，禁止截断后当作正常值。

| 操作 | 请求 |
| --- | --- |
| S、影调、暗角读取 | `GET /get_mcon.cgi?mode=ID` |
| H 读取 | `GET /get_mcon.cgi?mode=(8000 OR ID)` |
| L 读取 | `GET /get_mcon.cgi?mode=(C000 OR ID)` |
| S、影调、暗角写入 | `GET /set_mcon.cgi?mode=ID&value=4550VVVV` |
| H 写入 | 同上，值为 `4551VVVV` |
| L 写入 | 同上，值为 `4552VVVV` |

`VVVV` 为有符号 16 位**滑块档位**的补码，不是枚举下标、角度、EV 或原生系数。H/L 只接受 COLOR 的 48 个色区 ID。H+3 的例子：`mode=039F&value=45510003`；L−2：`mode=039F&value=4552FFFE`。H+3 对应原生 H −3000；L−2 对应原生 L −50。L 的非线性映射沿用配方格式定义。

| COLOR 槽 | 色区 ID，按物理记录顺序 | 高光 / 中间调 / 阴影 ID | 暗角 ID |
| --- | --- | --- | --- |
| 1 | 927…938 | 963 / 964 / 965 | 1667 |
| 2 | 939…950 | 966 / 967 / 968 | 1668 |
| 3 | 951…962 | 969 / 970 / 971 | 1669 |
| 4 | 1655…1666 | 1672 / 1673 / 1674 | 1670 |

上表 ID 是十进制，发请求前转换为十六进制。**不能**把轮盘索引直接加到首 ID：轮盘索引 0…11 对应物理索引 `[0,6,1,7,2,8,3,9,4,10,5,11]`。

完整配方的逻辑 40 值顺序固定为：轮盘 H ×12、轮盘 S ×12、轮盘 L ×12、阴影、中间调、高光、暗角。范围：H/L −7…+7，S −5…+5，三段影调 −7…+7，暗角 −5…+5。沿用 [ep7-film-recipe-v1](recipe-format.md)，名称和三项拍摄建议不写进相机。

## 结果和失败语义

| 结果 | 客户端解释 |
| --- | --- |
| 能力查询不等于 EP71 | 不兼容；不写，不尝试无标记回退 |
| 标记写入 HTTP 200 | 原厂应用事件完成路径的结果；**仍必须回读，不是持久化收据** |
| HTTP 520 | 原厂解析失败、非法 ID/轴/范围/标记或应用等待失败等；沿用一个状态，不虚构细分固件错误码 |
| H/L 读取 `80000000` | 非法/不支持的轴 ID；不得当中性值或补零 |
| 已支持单元尚未初始化或持久单元格式无效 | H/L 读取及成像按中性 0；不触发保存或刷新 |
| 超时、断连、响应丢失或回读不同 | 可能已部分应用或仍有一个排队编辑；停止写入，读取实际值并报告不确定状态 |

保留整个 `4550…455F` 高半字族；其中只有 `4550/4551/4552` 合法。非法组合在到达原始 setter 前拒绝；正常无标记命令仍走原厂路径。过长或含非十六进制字符的标记值不得借解析器截断绕回原始写入。

每次只允许一个在途请求。客户端先完整校验 40 值，再自动备份原槽，按逻辑顺序只写差异，建议间隔 50 ms，最后回读全部 40 值。50 ms 取自上游经验，**不是 E-P7 实测安全时限**。没有相机侧全配方事务、取消、重试幂等或自动回滚保证；写操作一律不自动重试。

发生不确定结果时，即使随后的读取暂时相同，也不能证明排队任务已取消。保留本地阻止再次写入的标记；机主手动重新连接 Wi-Fi 后再完整读取、确认并显式解除标记。恢复备份同样需要能力检查、先备份、写入和回读。

## 存储与成像边界

H/L 使用候选 A 的原厂 part 1 API，候选 u32 格式为 `0xe741CCVV`；VV 为 H/L 两个有符号 4 位，CC 为 VV 的逐位反码，−8 或不认识的版本按中性。此格式不提供事务或掉电保护。

带标记的值经过原厂待处理 ID/type/value、事件 `041B0011`、应用设置分派。H/L 写入后以原 S 值调用正常注册设置机制；S/影调/暗角使用真实有符号档位。原厂 `0xf6fa` 当前记录的每个 S 单元写入后，同点发布一对 H/L 到只读使用的 RAM 镜像；启动/召回刷新循环复用此入口。镜像随代码段加载先为零，图像路径不直接读取 ACTIVE。

v2 的图像配置身份和 v3 的紧凑身份规则保留，但数值来自当前已发布镜像。导入期间允许一张处理中的照片混用新旧**逐值**编辑结果；没有全槽快照。真实非易失保存、冷启、Myset、重置、原厂恢复和跨核/缓存行为必须按 B4 实拍确认。
